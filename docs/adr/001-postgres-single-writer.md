# ADR-001: Postgres как единый источник правды (Single-Writer)

## Контекст
Нам нужно надежно хранить метаданные объектов (бакеты, ключи, размеры, ETag). Мы работаем в режиме solo-разработки, поэтому не можем позволить себе сложные распределенные консенсусы (Raft/Paxos) на старте.

## Решение
Используем PostgreSQL в режиме `single-writer`. Это значит, что только один инстанс нашего приложения (и только он) имеет право писать в базу данных. Чтение может масштабироваться через реплики (в будущем).

## Последствия
- **Плюсы:** 
  - Транзакции ACID из коробки.
  - Простота реализации на старте.
  - Легко тестировать через `testcontainers`.
- **Минусы:** 
  - Это Single Point of Failure (SPOF). Если Postgres упадет, мы не сможем писать новые объекты.
  - Нет горизонтального масштабирования записи.
- **Когда пересмотреть:** Когда нагрузка на запись превысит возможности одного сервера, или когда потребуется отказоустойчивость на уровне нескольких дата-центров (тогда смотрим в сторону Raft/etcd).
