# Cost Model — s3vault

Модель экономии затрат на хранение за счёт дедупликации (content-addressed blobs) и сравнение с «наивным» хранением (каждый объект — отдельный файл).

---

## 1. Как работает дедупликация в s3vault

1. Каждый объект (`PutObject`) стримится через **chunker** (фиксированные чанки), для каждого чанка считается **SHA-256**.
2. Если blob с таким хэшем **уже есть** — новый файл **не пишется**, создаётся только запись в `blob_refs` (ссылка объекта на blob).
3. Если blob **новый** — он пишется **один раз** на диск (FSStore / ReplicaStore).
4. При удалении объекта — удаляется **ссылка** (`blob_refs`), а blob удаляется **только** когда счётчик ссылок = 0 (GC).

**Итог:** на диске хранится **уникальное содержимое**, а не копии.

---

## 2. Формула экономии

Обозначим:
- `N` — общее число объектов.
- `S` — средний размер объекта (байт).
- `U` — доля **уникального** содержимого (0..1). Например, `U = 0.3` значит, что 30% объектов уникальны, 70% — дубликаты.
- `C` — стоимость хранения 1 ГБ/мес (например, `$0.02` для локального диска или `$0.023` для S3 Standard).
